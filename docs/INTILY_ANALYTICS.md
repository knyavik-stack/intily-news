# Intily — аналитика простым языком

**Дата:** 2026-09-08

## 1. Два экрана

### Intily AI News Publisher

Показывает текущий production cycle: входной поток, фильтрацию, кандидатов, admission, публикацию, AI provider, audience-fit и media path.

### Intily Production Monitor

Показывает историю системы за 24 часа, 7 дней и сохранённую историю: публикации, кандидатов, причины отсутствия публикаций, здоровье источников, audience-fit, image delivery, provider/failover и последние циклы.

## 2. Актуальный score flow

```text
RSS / discovery
   ↓
base editorial score: 0–70
   ↓
PRE-AI gate = 40
   ↓
AI переводит + пересказывает + оценивает audience-fit 1–10
   ↓
AI contribution = audience_score × 3 (+3…+30)
   ↓
FINAL score = min(100, base + AI contribution)
   ↓
FINAL publication gate = 55
   ↓
Telegram
```

**55/100 — единственный текущий финальный порог публикации.**

Pre-AI 40 не означает автоматическую публикацию. Кандидат 40–54 проходит AI-редактуру; после AI итог должен быть ≥55. Финализированный элемент <55 не остаётся в durable queue.

AI оценивает не «интересность вообще», а конкретное последствие для русскоязычного AI-активного профессионала: предпринимателя, руководителя, product/marketing/sales/operations/finance специалиста, разработчика, AI-практика или power user.

Высокий score требует практического/стратегического consequence signal. Сам по себе бренд, valuation, funding, слух или прогноз не являются основанием для 8–10/10.

## 5. Математическое ожидание

Текущий prior для калибровки модели — рабочая гипотеза, не статистика реальных подписчиков. При распределении audience score 1–10, зафиксированном в `docs/SCORING_CALIBRATION_2026-09-07.md`, ожидаемый вклад AI-слоя составляет **19.74/30**.

Этот prior должен быть заменён эмпирическим распределением после накопления достаточной Telegram-аналитики.

## 6. Инвариант публикации

Публикация допускается только при:

```text
score_stage = final
AND final_score >= 55
```

`final_below_threshold` должен быть **0**. Значения 40–54 допустимы только как `pre_ai`.

## 7. Media analytics

Для каждого цикла фиксируются попытка, найденное изображение, валидация, отправка фото, text fallback, причина, источник, URL статьи, размеры и payload.

Текущая политика:

- источник изображения — publisher-first;
- Google News — discovery wrapper, не допустимый image host;
- изображения **>1,000,000 bytes** — жёстко отклоняются без resize/recompress;
- oversized/broken candidate пропускается, следующий candidate проверяется;
- поддерживаемая Telegram HTML-разметка сохраняется;
- небезопасные HTML-теги и ссылки санитизируются;
- **текст photo caption больше 1024 не обрезается**: вместо потери хвоста используется полный text-only fallback;
- валидное изображение с caption ≤1024 может уйти через `sendPhoto`.

## 8. Последний проверенный production run

Run #680 (`34219243075`) прошёл CI и опубликовал один материал с final score **69.1**. AI provider — Gemini, audience score **7/10**, прежний bonus был +14, потому что этот run произошёл до перехода на ×3.

Этот же run выявил реальный queue hygiene defect: `final_below_threshold=4`. Это было финализированное состояние очереди, а не доказательство публикации <55: editor gate уже блокировал такие элементы. Теперь finalized <55 удаляются из durable queue.

Run #680 также показал image fallback `HTTP 403`, поэтому live publisher-image delivery после новых изменений всё ещё требует подтверждения новым production cycle.
