# INTILY — калибровка scoring policy, 2026-09-06

## Факт production-проверки

Последний подтверждённый production run #326 завершился технически успешно, но не дал публикации.

Фактический вход: 403 материала.

Распределение score:

| Диапазон | Количество |
|---|---:|
| 0–39 | 273 |
| 40–49 | 101 |
| 50–59 | 29 |
| 60–69 | 0 |
| 70–79 | 0 |
| 80–84 | 0 |
| 85–89 | 0 |
| 90–100 | 0 |

Итого: 403/403 были ниже прежнего production threshold 60.0.

## Первопричина

Проблема была не в discovery: Google News дал 391 материал, прямые RSS ещё 12. Все 45 поисковых запросов Google News завершились без ошибок; один direct RSS источник (VentureBeat AI) вернул HTTP 429.

Проблема была в калибровке score относительно фактического распределения признаков. Модель требовала одновременно слишком много событийных/практических признаков для прохождения порога 60.

## Исправление

В `scripts/intily_scoring_policy.py` production admission threshold изменён с `60.0` на `50.0`.

В `scripts/intily_ai_news_runner.py` threshold теперь импортируется из scoring policy и принудительно передаётся в legacy publisher как `IMPORTANCE_THRESHOLD`. Это исключает расхождение между новой математикой и старым порогом publisher.

Весовая модель остаётся детерминированной и суммарно имеет 100 баллов:

- AI-релевантность — 30;
- влияние события — 20;
- практическая ценность — 15;
- новизна/конкретность — 10;
- качество источника — 10;
- доказательность — 5;
- свежесть — 5;
- значимость риска/проблемы — 5;
- низкий сигнал — штраф до −8.

География не входит в score и продолжает балансироваться отдельной publication-priority policy.

## Почему выбран именно 50

При прежнем production распределении 101 материал находился в диапазоне 40–49 и ещё 29 — в 50–59. Threshold 50 позволяет проверить жизнеспособность supply без возврата к слишком широкому старому отбору. Это калибровочный шаг, а не утверждение, что 50 является окончательным идеальным порогом.

Окончательная калибровка должна выполняться по нескольким реальным циклам с метриками:

1. score distribution;
2. unique candidates;
3. admission rate;
4. publication rate;
5. доля дублей;
6. качество опубликованных материалов.

## Следующая обязательная проверка

Нельзя считать исправление доказанным только по коммиту. Нужен следующий production cycle на новой версии `main`.

Успешный результат должен подтвердить одновременно:

- новый threshold реально применяется в runtime;
- появляются кандидаты `>=50.0`;
- часть кандидатов проходит duplicate/history gates;
- при наличии свободной очереди выполняется публикация при соблюдении publish interval;
- `SCORE_BUCKETS`, причины отсева и admission telemetry отражают новую политику.

Если при threshold 50 снова будет 0 кандидатов, следующий шаг — не дальнейшее слепое снижение порога, а feature-level calibration по реальным score components и проверка AI relevance gate.
